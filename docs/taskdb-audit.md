# TaskDB v1 safety audit

**Status:** Stage 1 audit complete with native-platform blockers recorded. This is implementation evidence, not a current-state specification. The owner later re-scoped the Stage 3 implementation to disposable WSL workspaces; that did not close the native validation blockers. The earlier multi-source pivot roadmap is retained as an [aspirational note](../ideas/taskdb-2.0-roadmap.md); current implementation details are in the [system specification](../spec/overview.md).

## Command and write paths

| Entry | Current route | Evidence and limit |
| --- | --- | --- |
| Desktop | React `runBackendCommand` -> `BackendTransport` -> long-lived Tauri shell `BackendSession` -> `tasks-backend --stdio` -> `executeCommand` | `src/platform/{backendClient,backendTransport,backendSession}.ts`; `src/backend/{cli,commands}.ts`. Responses correlate by request ID. `BackendSession` now rejects hung requests after 120 seconds, kills that child, ignores late events from it and starts a new process on the next request. The bounded behavior has a fake-process regression test, not native Tauri acceptance. |
| CLI / agent | `tasks-cli` parses flags, gets a current version for single-task edits, calls `executeCommand` | `src/backend/tasks-cli.ts:289-328`; `src/backend/commands.ts`. `--json` result differs from the JSON-lines envelope. An agent must reuse its own idempotency key after an uncertain result. |
| Web development | Loopback dev HTTP bridge calls the same `executeCommand` | `src/backend/devServer.ts`; not a packaged PWA or native acceptance path. |
| Android | Queued `handleAndroidRequest` -> `androidStorage` private SQLite, with optional SAF canonical folder | `src/platform/{backendTransport,androidBackendEngine,androidCanonicalWorkspace}.ts`; `src-tauri/src/{android_backend,android_workspace}.rs`. Shared protocol and some portable rules, but not the Node command/storage engine. |

Node commands take the workspace lock, open the cache and run `syncCanonicalWorkspace` before dispatch (`src/backend/commands.ts`). Task commands then use `withCanonicalTransaction` to commit activity/receipt/cache and canonical file replacements (`src/backend/tasks.ts`, `src/backend/canonicalWorkspace.ts:1571`). The pending-operation journal bridges the non-atomic file+SQLite interval: `reconcilePendingOperation` finishes files and restores the cached receipt on next command (`canonicalWorkspace.ts:1358-1425`). Android stages intended/previous SAF file contents in private SQLite, writes and verifies selected files, then completes the private transaction; `recoverPendingWrite` refuses an unrelated edit and requires the original folder (`androidCanonicalWorkspace.ts:805-861`). SAF has no multi-file atomic commit.

## Evidence captured so far

- Final Stage 1 gate: `pnpm check`, `pnpm test` (**112/112**, including timeout and committed-write restart/replay), `pnpm test:sidecar` (both Linux x86_64 SEA executables, FTS5 probe + CLI JSON), and `pnpm lint` passed. These are backend/packaging probes, **not** native desktop UI acceptance or a mid-write kill. The SEA injection printed `.note` warnings despite successful probes.
- A disposable Stage 0 CLI smoke created/listed/completed a classified task and yielded canonical workspace, task and root-order files.
- `scripts/fixtures/taskdb-v1/sync/` now holds four synthetic, valid-hash v1 tasks with root/child order. In an independent scratch root, `task.list` rebuilt its cache (4 tasks; 2 `@planning`, 1 uncategorized, 1 done, 1 paused), verified the child/dependency link, `workspace.backup` passed SQLite `PRAGMA integrity_check`, `workspace.export` + `workspace.restore` created another 4-task workspace with matching IDs/relationships, and `workspace.rebuild` invalidated an old expectedVersion (`STALE_TASK_VERSION`). The restored workspace intentionally got a **new** workspace ID. The read-only fixture stays in the repo; both databases and exports were temporary.
- [Development and validation](development.md) records a 2026-09-24 Android emulator standard-provider build, export and seeded-pending-write recovery; the missing process-kill/physical-provider tests are still limitations, not successes of this audit.
- This session is **WSL2**, not Omarchy/native Linux (`uname` reports `microsoft-standard-WSL2`). `mise` and Google's `android` CLI are unavailable here even after attempting the project-prescribed environment activation; `webkit2gtk-4.1` is also missing. The native Linux Tauri webview and Android emulator cannot be accepted from this host. Windows PowerShell interop exists, but a Windows scratch checkout/UI session has not been established for this audit.

## Discrepancies and stop-go

- **Passed:** a copied canonical v1 fixture rebuilds its cache and restores from a snapshot to a new root. Old optimistic versions become stale. CLI committed writes replay after restart. A hung desktop-session request fails within a bound and cannot let a late event from its old child kill the replacement. These checks support further **spec and conformance** work on disposable v1 data.
- **Unproven native M1:** WSL2 lacks Google's Android CLI, Omarchy `mise`, and WebKitGTK; Windows interop does not by itself validate a packaged UI. No process-kill during a real Android SAF write or third-party/physical-provider acceptance. Run the README native checks on a real host before claiming platform readiness. An actual sidecar mid-write kill/retry and packaged Tauri pending-call check remain worthwhile.
- **Known contract difference:** Android `task.update` requires both `title` and `descriptionMarkdown`; Node accepts partial fields. Specify the common subset or reconcile it before freezing v0. Source-scoped references, Uncategorized selection, adapter capabilities and multiple roots are proposed 2.0 behavior, not v1 promises.
- **Decision:** Stage 1's audit gate is met by evidence, reproducible checks and recorded blockers. Stage 2 may freeze and test a narrow contract. **Do not begin Stage 3's controller extraction or claim native release acceptance until the native M1 blockers are tested on a capable host or explicitly re-scoped by the owner.** Keep all personal roots untouched.
