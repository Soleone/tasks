# Platforms

This is the only place platform differences are listed. Everything else in the client spec applies everywhere.

## Desktop, Android and web

Android runs the desktop app's UI and the same backend, bundled in the app.

| Rule | Desktop | Android | Web |
| --- | --- | --- | --- |
| `platform.open-workspace` | Opens the remembered Tasks home; only a small pointer to it, and the window's size and position, live in the app's own storage. The first launch asks to create a home (suggested: `Tasks` in the user folder, outside OneDrive) or open an existing one, typed or chosen with Browse… in the system folder picker, and shows the sync folder to add to Syncthing. A missing home is reported with Retry, never replaced. Choosing another home from Settings can go back to the current one. Opening another home first finishes pending task changes and home saves, trying a failed save once more; while a task change is unfinished or unresolved, or a save or the close fails, it stays on this home and says why. A moved home asks before keeping its history; a copied one offers a new history | As desktop, but the home is typed: there is no Browse…. The home is a path on shared storage (suggested: `/storage/emulated/0/Tasks`) so Syncthing can sync its `sync/` folder, which needs all files access; the app asks for it on launch | The hosted build opens a home kept in this browser, empty on the first visit; changes and undo survive reloads. A Show example tasks switch, bottom left, flips at once and adds the example tasks, which come into focus from a quick blur, or removes them again, edited or not, as they blur away; they stay out of undo, and quick flips are applied in order. Removed examples are purged unless that would also purge the visitor's own canceled tasks; then they stay under Canceled. Download the app, bottom right, links to the downloads. Where there's no room beside the list the switch and button lose their labels, and where the quest card reaches under them they sit above it. Settings › Data says the tasks stay in this browser and links to the apps instead of showing paths. Under the dev server, its home (a copy of the fixture, or the kept copy of the owner's real folder) opens directly, and a home picked by hand is shown and confirmed in the window before anything loads |
| `platform.add-image` | Images are added by pasting (`attach.paste`) | Add image in the editor opens the system photo picker. Choosing an image adds it to the draft through the same type, size and count limits as pasting; it belongs to the task only when saved. Canceling the picker leaves the draft unchanged. Save is unavailable until selection has finished. Copy/paste remains available | As desktop |
| `platform.share-image` | Not available | Share image… in the image preview opens the system share sheet with the displayed image, not a link or a Tasks folder path. The receiving app gets read access to that temporary image only; the original stays unchanged. Failure says why and leaves the preview and draft open | Not available |
| `platform.copy-image` | Copies the image to the system clipboard | As desktop | As desktop where the browser allows writing images; otherwise says it can't |
| `platform.window-state` | The window reopens at its last size and position, maximized if it was. A position on a monitor that is gone is dropped and the system places the window | Not applicable | Not applicable |
| `platform.uninstall` | Uninstalling never touches the Tasks home. The Windows uninstaller also keeps the app's own data (the pointer to the home and the window's size and position) even when its delete box is ticked, and says so, so a reinstall opens the same home | Uninstalling removes only the app's private files, including the pointer; the home on shared storage stays, and a reinstall opens it again | Not applicable |
| `platform.update` | Once per start, the app asks GitHub for the latest release. A newer version shows a toast with Update that stays until it is used or closed; a failed check says nothing. Update downloads the signed update, then saves and closes the home as opening another home does, so an unfinished task change keeps it open and says why. The update then installs in place without asking anything and Tasks restarts: on Windows the installer runs in update mode, on Linux the AppImage file is replaced. A failed update says why and offers Retry | Not available: a new version is the APK attached to the GitHub release, installed by hand | Not applicable |
| `platform.app-menu` | On Linux the AppImage puts Tasks in the app menu each time it starts, pointing at wherever the file is kept; the Windows installer adds the Start menu entry | Installed apps show in the launcher | Not applicable |
| `platform.cli-location` | The CLI is the app's own backend executable: `tasks-cli.exe` beside `Tasks.exe` on Windows, inside `Tasks.app` on macOS. An AppImage holds it only while the app runs, so on each start of a new version the app copies it to `~/.local/share/tasks/tasks-cli` and links it from `~/.local/bin/tasks-cli` unless something is already there. Settings shows the path (`settings.agents`) | Not available | Not available |
| `platform.global-focus` | Two global hotkeys, set in Settings (`settings.hotkey-record`), work from any app: one brings the window forward, the other also opens the New task editor. A hotkey that can't be registered at start says so in a toast. Launching Tasks again brings the running window forward instead of starting a second one; with `--new-task` it also opens the editor. Hyprland binds use those launches (`settings.hotkey-hyprland`) | Not available | Not available |
| `platform.capture` | The global New task hotkey and `--new-task` (`platform.global-focus`) | Long-pressing the app's icon offers New task, which opens the app on the New task editor. Tasks is also a share target for text, links and PNG, JPEG, WebP or GIF images: sharing opens the New task editor filled in, with nothing saved until Save. A shared page's name is the title and its text or link the notes; text without a name puts its first line in the title and the rest in the notes. A shared image is added to the draft under the limits of `platform.add-image`, and one that can't be read says why. The title goes through the editor's shorthand like typed text. While an editor is already open, the launch waits until the app next comes forward with none open | Not available |
| `platform.moves` | Keyboard moves: shortcuts and the editor's shorthand and `Tab` keys. A quest step done with the mouse counts but teaches the key (`quest.pointer`) | Touch moves: New task, saving, the status icon, tapping and long-pressing a task, Effort, Move under, Blockers, the header counts and the keyboard bar's `@`, `#` and `!`. Any path to a move learns it | As desktop |
| `platform.mod-key` | Shortcut hints write `Ctrl/⌘` as `Ctrl`, or `⌘` on macOS. Either key works. On macOS hints also write `Alt` as `⌥`, and `⌥+T` opens themes even though Option changes the letter it types | As desktop, for a physical keyboard | As desktop, by the browser's system |
| `platform.quest-card` | The quest card is docked below the list | The card sits under the header, so the soft keyboard never hides it | As desktop |
| `platform.keyboard-bar` | No bar | While the editor is open, a bar above the soft keyboard has Esc at the far left, then `@`, `#`, `!`, Left and Right, and Save (Add for a new task) at the far right, with no Tab keys. Save saves from any field. Esc acts like physical Escape in the focused editor field; when that closes the editor, the tap never reaches the list under it. Markers insert once per tap; arrows move the text caret and repeat while held, stopping on release or cancellation. The bar never takes focus. Markers and arrows from the image row go to the title. Physical Tab navigation is unchanged | As desktop |
| `platform.swipe-back` | On a touchscreen, as Android | A quick one-finger swipe to the left acts like `Escape` for whatever has focus: it closes a dialog or panel, cancels the editor, leaves a lens, narrows the selection, then resets filters. A swipe that starts in a text field, on a toast, or on something that scrolls or drags sideways itself, such as the theme ring, keeps its own meaning. Slow, short or slanted drags do nothing | As Android, on a touchscreen |
| `platform.editor-buttons` | As `edit.buttons` | No Cancel or Save in the editor: the keyboard bar's Esc cancels, and its Save or the soft keyboard's Go in the title saves. While the description is closed, a muted "Add a description…" line stands where it opens and opens it on tap. That line and the pills' remove targets reach past what they draw, so a finger hits them. Scrolled into view, the editor keeps clear of the keyboard bar | As desktop |
| `platform.toolbar-cell` | Toolbar cells share a compact, consistent size | As desktop | As desktop, for mouse and touch |
| `platform.prefs-scope` | Preferences and undo records belong to the Tasks home and load before the list shows. A home without settings takes this browser's earlier preferences, once. The browser storage keeps a copy of the theme only so the first paint has the right colors. A preference that can't be saved says so | As desktop | As desktop, through the browser's or the dev server's home |

## iOS

Experimental: built only as an unsigned test IPA and not yet run on an iPhone. It behaves as Android, except:

- Opening a home: the home is a typed path inside the app's own folder (suggested: `/Tasks`), which the Files app shows under On My iPhone › Tasks, so a sync app can sync its `sync/` folder. No permission is asked.
- Sharing an image: closing the share sheet without choosing is not a failure.
- Updating: a new version is a new IPA, installed by hand.
- Uninstalling removes the app's folder, and the Tasks home in it.
