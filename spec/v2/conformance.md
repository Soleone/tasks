Storage providers must not relax the contract by inventing empty scans or silently overwriting partial bytes.

## Corpus checks versus execution

`node --test scripts/taskdbV2Spec.test.mjs` verifies case identities/profiles/anchors, required case references/error names, golden root structure/graph/field preservation/order and no canonical-local fields. It does NOT execute actions, implement a shorthand parser, run migration/doctor or call a v2 backend. Do not report its passing tests as “all v2 cases passed.” It only confirms that a corpus for those cases exists coherently.

`src/backend/v2CanonicalReader.ts` is an isolated read-only Node filesystem entry, with strict UTF-8/JSON and model/graph validation. It records exact byte observations, reports known conflict copies separately and refuses known escapes/mixed roots; the file helper itself does not initialize data, project versions, write files, migrate or recover journals. The separate gateway/cache and update modules described below supply local authority and the bounded write subset. `v2CanonicalReader.test.ts` materializes the 15 model corpus cases independently, preserving input bytes; additional focused checks cover the golden root, keys/ID ordering, duplicate escapes, BOM/non-finite values, entry refusal and a 10,000-node graph. Directory/file identity and repeated inventory/hash checks are best-effort observations, not a kernel-pinned cross-file snapshot or malicious directory-race sandbox. Static symlink refusal is not proof against every ancestor substitution/ABA race. Windows symlink tests explicitly skip if the privilege is absent; Android/provider behavior is not exercised.

The opt-in backend `--stdio --v2-root PATH --database CACHE_OUTSIDE_ROOT` advertises its supported commands in info: five original query commands, plus Linux-only `task.create`, `task.update`, `task.start`, `task.pause`, `task.complete`, `task.reopen`, `task.cancel`, `task.delete`, `task.move`, `task.dependency.add`, `task.dependency.remove`, `task.reorder`, `task.order.normalize`, `task.status.undo`, `task.status.undoMany`, `task.transitionMany`, `operation.undo`, `task.purgeCanceled`, `workspace.doctor.inspect`, `workspace.doctor.plan`, `workspace.doctor.apply`, `activity.list`, `workspace.archive`, `workspace.restore`, `workspace.migrateV1`, `workspace.init`, `workspace.rebuild`, and `workspace.recovery.resume`. No v1 watcher, registry or default database fallback runs in that mode. Strict byte framing preserves invalid UTF-8 and rejects malformed/duplicate envelopes with unsafe correlation null. `v2Gateway.test.ts` executes `protocol-version`, `protocol-schema`, `protocol-duplicate`, `protocol-nonfinite`, `query-literal`, `query-readiness`; `capability-refusal` requires specifically withheld doctor apply and is now skipped on writable Linux, not adapted to another command/profile; focused tests cover info states, exact projections, normalized filters, literal/ASCII search, paging/context, manual preorder, ties and scalar-safe search limits. `v2Cli.test.ts` checks actual subprocess restart, EOF/error continuation, explicit cache selection and inherited-v1-environment isolation. Retained-cache reopen preserves context and unchanged tokens; root/path/inode switching, cache copying/moving/replacement, full cache loss or safe-integer exhaustion rotate context. Authority now includes the resolved cache path and physical file identity, so copied/restored caches cannot replay the original cache's keys. Older root-only bindings rotate once on upgrade; no canonical data is changed. Original v1/foreign databases remain refused. Query evidence alone does not prove the write/recovery rules below. SQLite cache changes are local, not synced task effects. Inventory/hash checks remain best-effort, and malicious filesystem alias/race resistance is not a sandbox claim. ### Canonical-copy staging evidence

[The copy-stage primitive](../../src/backend/v2CopyStage.ts) builds an independent sibling stage for a caller-authorized absent/empty destination with an already-existing parent. It holds the same physical-root writer lock, refuses pending source updates and descriptor conflict copies, resolves disjoint paths before writing, records immutable local source/destination/file witnesses outside both canonical trees, copies exact canonical and reader-known task conflict bytes, writes the descriptor last, and rereads source/stage inventories, graph, model and hashes before writing a durable `verified_stage` report. Transport temporaries, Syncthing history and local cache/authority are not copied. The requested destination is never filled, overwritten, published or selected by this primitive. Retained intent/report files describe an unpublished backup stage, not idempotency receipts or a completed-request ledger.

After the final descriptor prefix a complete graph may exist in the private stage, but that alone is neither a verified completion nor permission to adopt/share it.

The stage-only primitive is **component evidence only**, not execution of migration/rollback or permission to adopt its private output. ### Recoverable capture and status

Linux-only `task.create` and `task.start/pause/complete/reopen/cancel/delete` now use the opt-in gateway and existing physical-root lock/cache/context/receipt/recovery boundaries. Default v1 clients/selection remain unchanged. Creation accepts only the declared literal/shorthand/content/parent inputs, uses open/P2 defaults, a UUIDv4 and one operation time, and prepends with pinned fractional indexing in the complete exact-parent scope, including hidden/canceled/tied siblings. The parent must exist and not be canceled. Status implements the accepted 30-transition matrix: delete cancels even done; cancel refuses done. Same-state requests store only a receipt. Status-only effects preserve edit time/order/links, use the fixed closure instant, clear closure on active states and never cascade.

[Creation inputs](../../src/backend/v2CreateInputs.ts), [status effects](../../src/backend/v2TaskStatus.ts), [create writer](../../src/backend/v2CreateWriter.ts) and [creation journal](../../src/backend/v2CreateJournal.ts) fix request/root/cache/directory/scope bytes, ID/time/key and intended task bytes. Initial local progress precedes immutable pending publication, so lost progress cannot be mistaken for a fresh capture. The exact complete private stage can survive file-write-before-binding. Durable `publicationStarted` precedes same-directory no-clobber linking; after that marker, an absent target is uncertain and requires preserved inspection, not recreation. Present targets need exact planned bytes and bound stage/target identity. No replacement-ID/key/gap/time plan is chosen on replay. UUID collisions, excessive allocation and near-exhausted authority refuse before canonical writes. Previews are non-consuming; their ID/time/version is hypothetical, not reserved for execution.
