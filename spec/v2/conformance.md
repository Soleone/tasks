# V2 conformance and support

**Status: accepted target, not implemented.** [Overview](overview.md). The [declarative corpus](../../scripts/fixtures/taskdb-v2/README.md) is normative expected input/outcome data, not a v2 reference implementation. Its format is independent of schema/protocol 2.

## Profiles and evidence

| Claim/profile | Required contract/cases | Current evidence |
| --- | --- | --- |
| File reader | Model, root/identity, graph, key grammar/comparison; malformed/partial bytes and mixed-root refusal | Partial Node filesystem helper: 15 model corpus cases plus targeted JSON/key/graph/golden/entry checks in [reader tests](../../src/backend/v2CanonicalReader.test.ts), on disposable WSL2 Linux roots (Node v22.22.3, kernel 6.6.114.1-microsoft-standard-WSL2); not full file-profile/native evidence |
| Command/query reader | Protocol/envelope/projection/input/query cases applicable to advertised commands | Explicit opt-in Node JSON-lines subset: info/get/list/category/tag, strict envelopes, local context/version projections; 7 corpus cases plus query/process checks. Not the complete protocol/query profile; default Node/Android v1 unchanged |
| Basic recoverable writer | Reader plus mutation/context/receipt/no-op/file-guard/journal cases for each supported write, including crash before/after local receipt commit and lost reply | Bounded Linux Node `task.update`/preview, SQLite receipt/activity and published-intent resume; real subprocess kill tests at four cuts plus divergence/missing/partial/arrival/cache-loss checks. Not the complete writer profile, undo, bulk or provider acceptance |
| Ordering maintenance | Exact vectors, ties, selected-key-unchanged versions, normalize, scope faults and grouped undo | Existing candidate tests; real two-peer Syncthing transport evidence, not app writer |
| Doctor/purge | Reviewed ambiguous/dangling links, preserved copies, plan/replay/cache-loss, cleanup interruption and referenced purge | Target cases only, no application proof |
| Migration/archive/restore | Full-field golden mapping, invalid sources, each stage interruption, destination/source guard, v1 rollback and fresh authority | Static golden root only; no converter/restore proof |
| CLI | Literal/shorthand flags, omitted-field updates, JSON/error output, original authority retained on retry | V1 friendly CLI unchanged; opt-in v2 JSON-lines backend checked across restart/EOF/invalid UTF-8. Friendly v2 verbs/retry preparation remain unsupported |
| Independent interoperability | A second implementation reads/writes the same complete files, reproduces keys and passes declared profiles | None; not a public standard claim |

Node/desktop, Windows 11 native, Omarchy native, Android standard SAF picker, third-party document providers and physical devices need separate reports. **Complete writer, native lifecycle and interoperability claims remain unproven.** The bounded Node query/update subset below has local command evidence, not complete protocol/provider conformance. WSL2 model/transport runs do not establish native conformance; browser builds cannot close M1. Android cannot keep its v1 title+description requirement or shared sync-revision versions while claiming these input/authority profiles.

A bounded implementation MAY advertise only a subset of protocol commands. It MUST report unsupported commands and refuse unsupported writes; it cannot label an unsupported case passed. Supported creation/update requires full model validation, exact-byte guards and safe pending outcomes, not only happy-path JSON. Cache loss deliberately fails old context/retries; no separate receipt ledger is required. Storage providers must not relax the contract by inventing empty scans or silently overwriting partial bytes.

## Corpus checks versus execution

`node --test scripts/taskdbV2Spec.test.mjs` verifies case identities/profiles/anchors, required case references/error names, golden root structure/graph/field preservation/order and no canonical-local fields. It does NOT execute actions, implement a shorthand parser, run migration/doctor or call a v2 backend. Do not report its passing tests as “all v2 cases passed.” It only confirms that a corpus for those cases exists coherently.

`src/backend/v2CanonicalReader.ts` is an isolated read-only Node filesystem entry, with strict UTF-8/JSON and model/graph validation. It records exact byte observations, reports known conflict copies separately and refuses known escapes/mixed roots; the file helper itself does not initialize data, project versions, write files, migrate or recover journals. The separate gateway/cache and update modules described below supply local authority and the bounded write subset. `v2CanonicalReader.test.ts` materializes the 15 model corpus cases independently, preserving input bytes; additional focused checks cover the golden root, keys/ID ordering, duplicate escapes, BOM/non-finite values, entry refusal and a 10,000-node graph. Directory/file identity and repeated inventory/hash checks are best-effort observations, not a kernel-pinned cross-file snapshot or malicious directory-race sandbox. Static symlink refusal is not proof against every ancestor substitution/ABA race. Windows symlink tests explicitly skip if the privilege is absent; Android/provider behavior is not exercised.

The opt-in backend `--stdio --v2-root PATH --database CACHE_OUTSIDE_ROOT` advertises its supported commands in info: five original query commands, plus Linux-only `task.update`, `activity.list`, and `workspace.recovery.resume`. No v1 watcher, registry or default database fallback runs in that mode. Strict byte framing preserves invalid UTF-8 and rejects malformed/duplicate envelopes with unsafe correlation null. `v2Gateway.test.ts` executes `protocol-version`, `protocol-schema`, `protocol-duplicate`, `protocol-nonfinite`, `capability-refusal`, `query-literal`, `query-readiness`; focused tests cover info states, exact projections, normalized filters, literal/ASCII search, paging/context, manual preorder, ties and scalar-safe search limits. `v2Cli.test.ts` checks actual subprocess restart, EOF/error continuation, explicit cache selection and inherited-v1-environment isolation. Create, status/order/relationship changes, undo, doctor, init/rebuild, migration/archive/restore, bulk recovery and friendly v2 CLI remain unavailable. Windows/Android writable commands are deliberately withheld.

`v2QueryCache.ts` uses a separately identified SQLite query cache outside the canonical tree, never the v1 database schema. Retained-cache reopen preserves context and unchanged tokens; root/path/inode switching, cache copying/moving/replacement, full cache loss or safe-integer exhaustion rotate context. Imported byte changes and changed complete sibling sequences allocate non-reused local versions, conservatively invalidating every member of an affected scope, including selected-key-unchanged moves. Failed/incomplete scans do not import partial records. Cache tests cover reopen/loss, same-path root replacement, formatting/deletion/reappearance and canonical/foreign-cache refusal. Cache schema 2 adds context-scoped receipts and grouped update history transactionally. Authority now includes the resolved cache path and physical file identity, so copied/restored caches cannot replay the original cache's keys. Older root-only bindings rotate once on upgrade; no canonical data is changed. Original v1/foreign databases remain refused. Query evidence alone does not prove the write/recovery rules below. SQLite cache changes are local, not synced task effects. Inventory/hash checks remain best-effort, and malicious filesystem alias/race resistance is not a sandbox claim. Execution platform remains WSL2/Node v22.22.3; native/Android/provider and independent implementations remain untested.

### Bounded guarded update evidence

[Update inputs](../../src/backend/v2UpdateInputs.ts) implement literal omitted-field preservation, explicit clears, ASCII classification and replacement shorthand, including code/escape boundaries. [Input tests](../../src/backend/v2UpdateInputs.test.ts) apply all 14 corpus input vectors through the update parser, adapting create vectors to update arguments. This is grammar/component evidence, NOT execution of the unsupported create commands or an increase in the 22 fully materialized model/query corpus cases. [Receipt tests](../../src/backend/v2Receipts.test.ts) check exact request identity, historical payload persistence, actor/flag/payload mismatch and cache-loss refusal.

[The update writer](../../src/backend/v2UpdateWriter.ts) validates root/schema/context/shape before SQLite receipt lookup and replays before live task/graph checks. It observes the full root, checks expected versions, writes a durable immutable intent outside canonical data, rechecks bytes/inventory before atomic replacement, verifies final graph/bytes, then commits local versions/receipt/grouped actor history. No-op execution stores only a receipt; previews never execute or consume keys. `updatedAt` changes for content edits; closure/creation and omitted fields are preserved. Undo remains unsupported. Near-exhausted version budgets refuse execution before file writes rather than rotating authority mid-write.

[Root-scoped local state](../../src/backend/v2LocalDomain.ts) is keyed by resolved path and physical identity under the same user's app-data profile, independently of cache choice. Participating same-device processes must share that profile. Its SQLite lock releases on process death; a published `pending.json` retains fixed request, IDs/time, old/new bytes and complete file witnesses until a durable completion. Root queries report pending work instead of treating unfinished bytes as completed tasks. Explicit resume accepts only original or planned-next bytes and unchanged inventory/other files; no rollback, resurrection or new IDs/times. Different-cache recovery is refused; complete loss at the original cache location allows explicit fresh-authority recovery but never validates an old-context retry. Malformed or unpublished `.preparing` evidence is preserved for manual inspection, not automatically repaired. Local state/profile loss, root replacement and missing journals are not reconstructable completed-receipt ledgers.

[Writer tests](../../src/backend/v2UpdateWriter.test.ts) check actual guarded updates, no-op/preview byte/version/activity preservation, historical replay even after a task disappears, identity mismatch, failed-precondition key reuse, cache loss/copy refusal and edits of closed tasks. [Recovery tests](../../src/backend/v2UpdateRecovery.test.ts) load test-only transforms into actual CLI subprocesses and send `SIGKILL` after published staging, after canonical replacement, before SQLite commit and after commit before reply/retirement. They also kill recovery after its own receipt commit to verify same-key cleanup retirement. They verify explicit resume, one operation/receipt result, changed/missing/partial/new-sibling refusal, cross-cache pending discovery/refusal and fresh-cache recovery. These are process-interruption tests on disposable WSL2 roots, not hardware power-loss, multi-file prefixes, native desktop, third-party-provider or distributed atomicity evidence. External editors/Syncthing may still race after final observations; no kernel-pinned CAS or malicious-filesystem sandbox is claimed. Retained pending intent is an operation journal, not a second durable ledger of successful requests.

Existing [candidate/rekey tests](../../scripts/taskdbV2Rekey.test.mjs) and [Syncthing transport probe](../../scripts/taskdbV2Transport.test.mjs) remain bounded experimental evidence. The proposal records their writer race/CRDT/power-loss limits. V1 regressions still run under `pnpm test`; they do not prove target compatibility without v2 execution.

For each future execution report record implementation/version, platform/provider, supported commands/profiles, fixture version and case IDs executed/passed/failed/unsupported, temporary-root setup, fault method/cut points, cache/recovery retention and residual limitations. Capture actual response/artifact evidence and verify original/target bytes. Keep expected fixture outcomes independent of implementation-generated values except declared opaque/time bindings.

Actual recovery proof must include interruption at every file prefix, after canonical verification but before receipt transaction, after receipt commit before reply, cleanup retirement, deletion and partial-byte writes; relevant preflight faults must leave zero operation writes. Actual conversion proof must verify v1 remains usable at every failed stage, full-field target equality, fresh-context adoption and rollback warnings about later v2 edits. Reusing the same code to produce expected and actual results is not independent conformance.

Promotion closes the spec/fixture gate only. The recoverable slice and native M1 gates remain open, with no production/personal-data conversion by these integrity tests.
