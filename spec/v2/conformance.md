# V2 conformance and support

**Status: accepted target, not implemented.** [Overview](overview.md). The [declarative corpus](../../scripts/fixtures/taskdb-v2/README.md) is normative expected input/outcome data, not a v2 reference implementation. Its format is independent of schema/protocol 2.

| CLI | Literal/shorthand flags, omitted-field updates, JSON/error output, original authority retained on retry | V1 friendly CLI unchanged; opt-in v2 JSON-lines backend checked across restart/EOF/invalid UTF-8. Friendly v2 verbs/retry preparation remain unsupported |
| Independent interoperability | A second implementation reads/writes the same complete files, reproduces keys and passes declared profiles | None; not a public standard claim |

Node/desktop, Windows 11 native, Omarchy native, Android standard SAF picker, third-party document providers and physical devices need separate reports. **Complete writer, native lifecycle and interoperability claims remain unproven.** The bounded Node query/update subset below has local command evidence, not complete protocol/provider conformance. WSL2 model/transport runs do not establish native conformance; browser builds cannot close M1. Android cannot keep its v1 title+description requirement or shared sync-revision versions while claiming these input/authority profiles.

A bounded implementation MAY advertise only a subset of protocol commands. It MUST report unsupported commands and refuse unsupported writes; it cannot label an unsupported case passed. Supported creation/update requires full model validation, exact-byte guards and safe pending outcomes, not only happy-path JSON. Cache loss deliberately fails old context/retries; no separate receipt ledger is required. Storage providers must not relax the contract by inventing empty scans or silently overwriting partial bytes.

## Corpus checks versus execution

`node --test scripts/taskdbV2Spec.test.mjs` verifies case identities/profiles/anchors, required case references/error names, golden root structure/graph/field preservation/order and no canonical-local fields. It does NOT execute actions, implement a shorthand parser, run migration/doctor or call a v2 backend. Do not report its passing tests as “all v2 cases passed.” It only confirms that a corpus for those cases exists coherently.

`src/backend/v2CanonicalReader.ts` is an isolated read-only Node filesystem entry, with strict UTF-8/JSON and model/graph validation. It records exact byte observations, reports known conflict copies separately and refuses known escapes/mixed roots; the file helper itself does not initialize data, project versions, write files, migrate or recover journals. The separate gateway/cache and update modules described below supply local authority and the bounded write subset. `v2CanonicalReader.test.ts` materializes the 15 model corpus cases independently, preserving input bytes; additional focused checks cover the golden root, keys/ID ordering, duplicate escapes, BOM/non-finite values, entry refusal and a 10,000-node graph. Directory/file identity and repeated inventory/hash checks are best-effort observations, not a kernel-pinned cross-file snapshot or malicious directory-race sandbox. Static symlink refusal is not proof against every ancestor substitution/ABA race. Windows symlink tests explicitly skip if the privilege is absent; Android/provider behavior is not exercised.

The opt-in backend `--stdio --v2-root PATH --database CACHE_OUTSIDE_ROOT` advertises its supported commands in info: five original query commands, plus Linux-only `task.update`, `activity.list`, `workspace.archive`, `workspace.restore`, `workspace.migrateV1`, and `workspace.recovery.resume`. No v1 watcher, registry or default database fallback runs in that mode. Strict byte framing preserves invalid UTF-8 and rejects malformed/duplicate envelopes with unsafe correlation null. `v2Gateway.test.ts` executes `protocol-version`, `protocol-schema`, `protocol-duplicate`, `protocol-nonfinite`, `capability-refusal`, `query-literal`, `query-readiness`; focused tests cover info states, exact projections, normalized filters, literal/ASCII search, paging/context, manual preorder, ties and scalar-safe search limits. `v2Cli.test.ts` checks actual subprocess restart, EOF/error continuation, explicit cache selection and inherited-v1-environment isolation. Create, status/order/relationship changes, undo, doctor, init/rebuild, bulk task recovery and friendly v2 CLI remain unavailable. Windows/Android writable commands are deliberately withheld.

`v2QueryCache.ts` uses a separately identified SQLite query cache outside the canonical tree, never the v1 database schema. Retained-cache reopen preserves context and unchanged tokens; root/path/inode switching, cache copying/moving/replacement, full cache loss or safe-integer exhaustion rotate context. Imported byte changes and changed complete sibling sequences allocate non-reused local versions, conservatively invalidating every member of an affected scope, including selected-key-unchanged moves. Failed/incomplete scans do not import partial records. Cache tests cover reopen/loss, same-path root replacement, formatting/deletion/reappearance and canonical/foreign-cache refusal. Cache schema 2 adds context-scoped receipts and grouped update history transactionally. Authority now includes the resolved cache path and physical file identity, so copied/restored caches cannot replay the original cache's keys. Older root-only bindings rotate once on upgrade; no canonical data is changed. Original v1/foreign databases remain refused. Query evidence alone does not prove the write/recovery rules below. SQLite cache changes are local, not synced task effects. Inventory/hash checks remain best-effort, and malicious filesystem alias/race resistance is not a sandbox claim. Execution platform remains WSL2/Node v22.22.3; native/Android/provider and independent implementations remain untested.

### Bounded guarded update evidence

[Update inputs](../../src/backend/v2UpdateInputs.ts) implement literal omitted-field preservation, explicit clears, ASCII classification and replacement shorthand, including code/escape boundaries. [Input tests](../../src/backend/v2UpdateInputs.test.ts) apply all 14 corpus input vectors through the update parser, adapting create vectors to update arguments. This is grammar/component evidence, NOT execution of the unsupported create commands or additional fully materialized corpus execution; the 36-case total below includes separate public copy and migration cases. [Receipt tests](../../src/backend/v2Receipts.test.ts) check exact request identity, historical payload persistence, actor/flag/payload mismatch and cache-loss refusal.

[The update writer](../../src/backend/v2UpdateWriter.ts) validates root/schema/context/shape before SQLite receipt lookup and replays before live task/graph checks. It observes the full root, checks expected versions, writes a durable immutable intent outside canonical data, rechecks bytes/inventory before atomic replacement, verifies final graph/bytes, then commits local versions/receipt/grouped actor history. No-op execution stores only a receipt; previews never execute or consume keys. `updatedAt` changes for content edits; closure/creation and omitted fields are preserved. Undo remains unsupported. Near-exhausted version budgets refuse execution before file writes rather than rotating authority mid-write.

[Root-scoped local state](../../src/backend/v2LocalDomain.ts) is keyed by resolved path and physical identity under the same user's app-data profile, independently of cache choice. Participating same-device processes must share that profile. Its SQLite lock releases on process death; a published `pending.json` retains fixed request, IDs/time, old/new bytes and complete file witnesses until a durable completion. Root queries report pending work instead of treating unfinished bytes as completed tasks. Explicit resume accepts only original or planned-next bytes and unchanged inventory/other files; no rollback, resurrection or new IDs/times. Different-cache recovery is refused; complete loss at the original cache location allows explicit fresh-authority recovery but never validates an old-context retry. Malformed or unpublished `.preparing` evidence is preserved for manual inspection, not automatically repaired. Local state/profile loss, root replacement and missing journals are not reconstructable completed-receipt ledgers.

[Writer tests](../../src/backend/v2UpdateWriter.test.ts) check actual guarded updates, no-op/preview byte/version/activity preservation, historical replay even after a task disappears, identity mismatch, failed-precondition key reuse, cache loss/copy refusal and edits of closed tasks. [Recovery tests](../../src/backend/v2UpdateRecovery.test.ts) load test-only transforms into actual CLI subprocesses and send `SIGKILL` after published staging, after canonical replacement, before SQLite commit and after commit before reply/retirement. They also kill recovery after its own receipt commit to verify same-key cleanup retirement. They verify explicit resume, one operation/receipt result, changed/missing/partial/new-sibling refusal, cross-cache pending discovery/refusal and fresh-cache recovery. These are process-interruption tests on disposable WSL2 roots, not hardware power-loss, multi-file prefixes, native desktop, third-party-provider or distributed atomicity evidence. External editors/Syncthing may still race after final observations; no kernel-pinned CAS or malicious-filesystem sandbox is claimed. Retained pending intent is an operation journal, not a second durable ledger of successful requests.

### Canonical-copy staging evidence

[The copy-stage primitive](../../src/backend/v2CopyStage.ts) builds an independent sibling stage for a caller-authorized absent/empty destination with an already-existing parent. It holds the same physical-root writer lock, refuses pending source updates and descriptor conflict copies, resolves disjoint paths before writing, records immutable local source/destination/file witnesses outside both canonical trees, copies exact canonical and reader-known task conflict bytes, writes the descriptor last, and rereads source/stage inventories, graph, model and hashes before writing a durable `verified_stage` report. Transport temporaries, Syncthing history and local cache/authority are not copied. The requested destination is never filled, overwritten, published or selected by this primitive. Retained intent/report files describe an unpublished backup stage, not idempotency receipts or a completed-request ledger.

[Copy-stage tests](../../src/backend/v2CopyStage.test.ts) exercise all golden fields through exact byte equality, raw invalid-UTF-8 conflict preservation, authorized destination aliases, overlap/occupied output refusal, partial/mixed source bytes, descriptor conflict refusal, pending-source refusal and a second byte-preserving restore stage with fresh local context. [Fault tests](../../src/backend/v2CopyStageFaults.test.ts) kill actual Node subprocesses after every 0–5 file prefix, and inject prewrite source edits/arrivals, late destination occupation, foreign stage entries and partial stage bytes. Source/external bytes are preserved, no requested destination is published and no verified report is produced on failure. After the final descriptor prefix a complete graph may exist in the private stage, but that alone is neither a verified completion nor permission to adopt/share it.

The stage-only primitive is **component evidence only**, not execution of migration/rollback or permission to adopt its private output. The separate public copy controls below supply archive/restore command evidence; the primitive itself still performs no publication, selection or receipt integration. Retain failed stage-only artifacts for inspection rather than automatically adopting, deleting or retrying them. Existing-parent/Linux-only boundaries and best-effort filesystem observations remain intentional limits, not Windows/SAF/provider, malicious-filesystem, distributed snapshot or hardware power-loss acceptance.

### Public archive/restore and copy recovery

[Copy commands](../../src/backend/v2CopyWriter.ts) now execute `workspace.archive` and `workspace.restore` under selected-root/cache authority. Both require a selected complete schema-2 root; restore names a separately validated schema-2 source. Source bytes, selected-root task versions and activity remain unchanged. Destinations are explicitly authorized absent/empty physical directories with existing parents, disjoint from source/selection and outside cache/app-data. Previews verify inputs without consuming keys or creating a stage. Historical receipt replay precedes source/destination/live graph checks, including after a named source disappears; changed actor/flags/args refuse reuse. No selection switch, v1/SQLite snapshot import or old-authority transfer occurs.

[Copy journals](../../src/backend/v2CopyJournal.ts) retain fixed raw bytes/hashes, request, operation ID and source/destination bindings outside canonical data before staging. Durable progress binds the private stage/task directory identities and exact written prefix. Explicit resume accepts recorded files plus at most the next exact complete file whose write preceded progress commit; missing recorded files, partial/unexpected bytes or wrong bindings stop. The descriptor is last. Complete stage inventory/model/graph/bytes and unchanged source are verified before a durable report and same-parent directory publication. A local target-root reservation blocks queries/writes on the published destination until outcome/receipt completion; info directs recovery to the original selected root/cache. [Shared pending discovery](../../src/backend/v2Pending.ts) and [recovery](../../src/backend/v2Recovery.ts) retain existing update semantics, then retire target reservation/progress/report/owner intent only after SQLite success. None is a separate successful-request ledger.

[Command tests](../../src/backend/v2CopyWriter.test.ts) materialize `archive-restore` and `destination-overlap`, preserving independent exact source bytes and fixture expectations. They additionally check raw conflict preservation, previews, replay, aliases, source selection, invalid roots and copied-cache authority. [Copy recovery tests](../../src/backend/v2CopyRecovery.test.ts) run actual JSON-lines CLI subprocesses and kill both archive/restore at published intent, every 0–5 file prefix, verification, target reservation, directory publication, before/after receipt commit and target/evidence retirement. Ordinary subprocess restart/replay and recovery's own lost reply are checked. Source/stage/output edits/arrivals, partial/missing files, directory replacement, progress/report/reservation loss and different-cache recovery stop without overwriting or resurrection. Cache loss at the original location permits fresh-context explicit recovery with retained evidence, never old-context retry. Historical recovery receipts remain replayable even when corrupt cleanup evidence must stay pending.

**Limits:** unrecorded directory creation, unpublished/partial progress or malformed intent requires manual inspection, not guessed ownership. Lost profile/evidence cannot recreate completion authority; completed stage-only artifacts are not automatically adopted. Noncooperating editors can still race after final checks. Root locks are same-profile and bounded SQLite waits may refuse contending cross-root operations. Copy commands repeatedly rescan source/prefixes; large-collection performance is not validated. Writable capability remains Linux-only. Migration uses the separate v1-aware control described below. Native/provider, hardware power-loss, malicious-filesystem, full file/writer profile and independent interoperability acceptance remain open.

Fully materialized corpus execution is now **36 cases** (15 model, 7 protocol/query, 2 storage, 12 migration), not 112. The 14 adapted input vectors remain separate. Restored-context refusal using supported update is targeted evidence, not full execution of `restore-cache-authority`, whose final create command remains unsupported.

### Read-only v1 conversion component

[The v1 source reader](../../src/backend/v2MigrationSource.ts) verifies exact descriptor/task/order/sync field sets, strict decoded-member JSON/Unicode, workspace and exact filename IDs, v1 content hashes, lossless explicit-offset timestamps, terminal consistency, graph links/cycles and complete inactive-inclusive sibling sequences. It refuses unknown/conflicted/partial entries, descendant symlinks and conservatively ambiguous ASCII case spellings even on case-sensitive Linux. Known physical transport markers/history and transfer temporaries are excluded; SQLite never fills missing content. Errors carry affected path, optional task ID, field and a fixed reason without echoing task text. Repeated physical directory/inventory/hash observations are best-effort, not a writer lock, pinned snapshot, malicious-filesystem sandbox or distributed CAS.

[The converter](../../src/backend/v2V1Conversion.ts) uses existing v1 recognition spans, removes only metadata spans plus outer trim without collapsing other whitespace or applying v2 escapes, retains Markdown/line endings, IDs/edges/status/priority and timestamp instants, and allocates pinned `fractional-indexing@3.2.0` keys over every complete sibling sequence. The existing pinned library is now a runtime dependency, with no version/package addition. Conversion returns source witnesses, complete validated target models and deterministic file bytes **in memory only**. It creates no destination, manifest, stage, cache, context, receipt or selection.

[Converter tests](../../src/backend/v2V1Conversion.test.ts) pass 100 checks, including exact byte/full-field equality with the independent committed golden and eight adapted vectors: `migrate-golden`, `migrate-title-only-tokens`, `migrate-legacy-escape`, `migrate-offset`, `migrate-invalid-time`, `migrate-order-missing`, `migrate-unknown-field`, `migrate-markdown`. These check converter/source behavior, **not themselves command execution; separate public tests below execute those actions**. Focused checks add spacing/code/Unicode, legacy IDs, sorted edge membership, inactive order, retained legacy updatedAt/closure, empty collections/scopes, metadata/hash/entry/graph failures, safe diagnostics and Gregorian/offset/precision boundaries. [Source fault tests](../../src/backend/v2MigrationSourceFaults.test.ts) add 14 real disposable Linux subprocess checks: SIGKILL after each 0–7 source-file prefix, changed bytes/removal/arrival/conflict and root/task-directory replacement after initial reads. Source/external changes remain untouched; no target is published. Process kills do not prove staged migration recovery or hardware power-loss behavior.

These 114 read-only checks remain component evidence. Public migration execution below separately covers the corresponding command actions; do not count the component vectors a second time. Default v1 commands/UI remain unchanged; no personal data was inspected or converted.

### Guarded v1 migration and explicit rollback

[The Linux migration control](../../src/backend/v2MigrationWriter.ts) executes `workspace.migrateV1` on the explicitly selected canonical v1 root. Info supplies protocol-2 **control authority**, not v1 task versions; ordinary protocol-2 task queries/writes still require schema 2. The control uses a separate identified v2 SQLite cache, never an old v1 database. Current context/key and request identity rules match other controls; previews consume no key and publish nothing. Historical receipts precede live source/task/destination checks. [Descriptor-only control binding](../../src/backend/v2ControlRoot.ts) permits explicit recovery from the original v1 owner without admitting v1 as v2 task data.

[Migration evidence](../../src/backend/v2MigrationJournal.ts) augments the shared fixed copy intent with raw source bytes/hashes and root/task/order directory bindings. Before target writes, it retains an independently verified `taskdb.v1-migration-recovery` version-1 JSON archive under local app-data, outside source/destination, with exact original descriptor/task/order bytes encoded as base64. This is recovery data, not synced state or a completed-request/receipt ledger. It remains after successful journal retirement. Missing/divergent recorded backup or unpublished `.preparing` data requires preserved inspection, not automatic reconstruction. Source and fixed mapping are rechecked before each target file/publication; changed source fails `MIGRATION_CONFLICT`. Shared durable prefix/report/reservation logic writes the descriptor last, validates target model/graph/bytes against the fixed complete mapping and publishes a separate destination. The verified report and SQLite result identify source/destination, transformed IDs, recovery location, preserved v1 directory and a rollback warning; they never select a root or enable sharing.

[13 command tests](../../src/backend/v2MigrationWriter.test.ts) execute all eight mapping/source cases plus `migrate-destination` and `rollback`, with previews, shape/context/key failures, historical replay, incompatible cache and fresh authority. The rollback case explicitly selects the verified v2 root with a fresh cache, refuses old control authority, makes a v2 edit, then explicitly materializes the retained raw v1 archive into a separate disposable folder and opens it with the actual protocol-1 CLI. Every original v1 byte and task is preserved; the later v2 edit remains separately. This is explicit root/client selection, **not a new rollback command, UI migration or reverse converter**.

[47 CLI/recovery tests](../../src/backend/v2MigrationRecovery.test.ts) execute `migrate-interrupted` and `migrate-source-change`. Actual subprocess SIGKILL cuts cover fixed intent, independent backup, every 0–5 mapped-file prefix, verification, reservation, publication, before/after SQLite receipt commit, evidence retirement and recovery's own lost reply. Unbound stage creation/unpublished backup require inspection. Source formatting/missing/arrival/conflict/directory replacement, target/stage/backup/progress/report/reservation divergence/loss, copied/different/lost cache and changed intent refuse without repair/resurrection. Pre-intent source/destination races leave no intent, backup or target stage. Normal CLI restart replays the same completion. The bundled CJS backend also passes a disposable migration/replay/adoption/rollback smoke check.

Fully materialized corpus execution is **36 cases**, including all 12 migration cases, not 112. Input/converter component tests and candidate probes remain separate. Evidence is WSL2 Linux Node v22.22.3 process-interruption proof only. Pause **all v1 writers and sharing yourself**: legacy writers do not participate in the new control lock, and arbitrary editors can race after observations. Sharing state cannot be verified from folder bytes. Do not select/share private stages; use only a completed published destination. Control-cache/profile loss and source-root replacement may require manual reconciliation; no hardware power-loss, malicious-filesystem sandbox, distributed CAS, large-collection performance, native provider or personal-data rollout is accepted. Friendly v2 CLI, UI adoption and Windows/Android writes remain separately queued.

Existing [candidate/rekey tests](../../scripts/taskdbV2Rekey.test.mjs) and [Syncthing transport probe](../../scripts/taskdbV2Transport.test.mjs) remain bounded experimental evidence. The proposal records their writer race/CRDT/power-loss limits. V1 regressions still run under `pnpm test`; they do not prove target compatibility without v2 execution.

For each future execution report record implementation/version, platform/provider, supported commands/profiles, fixture version and case IDs executed/passed/failed/unsupported, temporary-root setup, fault method/cut points, cache/recovery retention and residual limitations. Capture actual response/artifact evidence and verify original/target bytes. Keep expected fixture outcomes independent of implementation-generated values except declared opaque/time bindings.

Actual recovery proof must include interruption at every file prefix, after canonical verification but before receipt transaction, after receipt commit before reply, cleanup retirement, deletion and partial-byte writes; relevant preflight faults must leave zero operation writes. Actual conversion proof must verify v1 remains usable at every failed stage, full-field target equality, fresh-context adoption and rollback warnings about later v2 edits. Reusing the same code to produce expected and actual results is not independent conformance.

Promotion closes the spec/fixture gate only. The recoverable slice and native M1 gates remain open, with no production/personal-data conversion by these integrity tests.
